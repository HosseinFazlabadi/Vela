# VLC extensions in Vela 1.1

Vela exposes every macOS extension API family registered by `GetLuaState` in the pinned VLC 3.0.24 source. The inventory lists 144 upstream function-table entries, including userdata methods and aliases, plus constructors, root functions and errno constants. This means API coverage; it does not certify every third-party script, hardware device, remote service or argument combination.

The engine-facing functions compile the original VLC bindings. The small adaptations obtain Vela's real current input and persistent audio output from the actual libVLC player. Objects, typed variables and choices, input items and metadata/statistics, configuration, streams and filters, XML readers, file handles, sockets/listeners/poll, errno, strings, VLM, OSD and volume use VLC's implementations. Volume uses VLC's 256 units at 100%, and changes may complete asynchronously. The build rejects engines other than the pinned ARM64 3.0.24 runtime.

Lua is 5.1.5 with VideoLAN's fixed-width bytecode, vararg fix and disabled native dynamic-module loading patches. Official bundled VLC bytecode and a compiled extension are exercised in tests. Install `.lua`, VLC-compatible `.luac`, `.vle`/ZIP with `script.lua` at its root, or a folder containing `script.lua`. Package `modules/*.luac` and `modules/*.lua` are searched before bundled modules. ZIP import rejects traversal, links and duplicate files, with 4,096 entries, 32 MiB per file and 128 MiB total limits. This is a trusted-script host, not a sandbox.

All dialogs use Vela's SwiftUI/AppKit interface. It implements the complete upstream dialog and widget method tables: buttons, labels, rich HTML, text/password fields, checkboxes, dropdowns, lists, images and spinning status icons; text/checked/value/selection operations; clear/delete; show/hide/title/update and finite/infinite animation. Dropdown values include both ID and label, including ID zero. Grid spans and size hints are mapped to native controls. Layout is bounded to 512 column positions, 10,000 row positions, matching spans and 16,384-point size hints. Native presentation revisions and edit acknowledgements prevent older callbacks from replacing newer edits or selections. `dialog:update()` publishes while a script is still working.

Playlist APIs operate on Vela's queue and library. IDs survive sorting/reordering and are shared by extension sessions. Add/enqueue preserve standard and custom metadata, duration hints and input options. Returned items are the real retained VLC input items used for playback, so edits persist across repeated lookups. Local files are preparsed. Vela's `ml` selector maps to its independently persisted media library; its main queue is flat. Service roots and nested items use the VLC SDK's discovery callbacks and input-item subtree events, including podcast feeds. This bypasses the public libVLC discoverer restriction on podcasts. The playlist context is a VLC object for variables and discovery, never a counterfeit private playlist structure. Fullscreen requests target Vela's main video window.

Capabilities control input, metadata and playing listeners; trigger-only scripts are supported. `playing_changed` receives VLC input states: 0 initial, 1 opening, 2 playing, 3 paused, 4 ended, 5 error. Menus and `trigger_menu` remain native. Active sessions rebind when playback settings recreate the engine. A 15-second deadline, `keep_alive`, instruction hooks and a watchdog cover script execution and interruptible VLC network waits. Managed `os.execute` commands preserve Lua 5.1 encoded wait statuses and run in a separate process group that is terminated on cancellation/deadline. Other native/standard-library operations that do not honor interrupts can still block. Cancellation tests cover a blocked network poll and an infinite Lua loop, including interpreter release.

Vela's extension data and engine configuration are separate from the original VLC app. `config.datadir()` points to the bundled VLC share directory; user/config/cache directories point into Vela's application-support directory. Windows-only APIs and libraries registered only in other VLC script contexts are outside the macOS extension API scope.

Tests exercise every root function-table entry for availability and real behaviors in each family. They include local HTTP/socket traffic, file IO, XML, VLM commands, metadata edits, stable playlist IDs, podcast episode trees, native dialogs, compiled modules/packages, lifecycle events and rebinding. VLSub's native dialog activation is checked; its online subtitle provider is not certified. The complete release report records the result and software-only hardware substitutions.

The pinned third-party corpus additionally exercises Speed Controller activation, rate changes and replacement settings dialogs, and Playlist Tracker activation, input events and state persistence. These checks cover the specific upstream commits in Tests/compatibility-fixtures.json; they do not certify their online services or every script in the ecosystem.
